# Retry storm detector

Spaniel reports a retry storm when at least three outbound HTTP client spans with the same parent, method and exact URL form a sequential chain. Every attempt except the last must have an OpenTelemetry error status or HTTP status 400 or greater; a redirect is never treated as a failure. Consecutive attempts must not overlap and must start within one second of the previous attempt ending. If both attempts carry `http.request.resend_count`, it must increase by one. A final successful attempt is included. These thresholds favor evidence over recall: ordinary successful repetition, parallel calls, long backoffs and redirects do not establish a retry storm.

The finding count is the number of observed attempts in the longest chain for that parent and operation. Its fingerprint displays elapsed time from the first start to the last end, including backoff. The `wasted_ns` field remains zero because elapsed time does not establish how much could be saved. The example span and parent link to the trace for inspecting the attempts. URL credentials, paths, query strings, span names and attribute values are not displayed in the finding. A hash of the matching identity supplies a stable finding ID, allowing late arrivals to update its evidence without duplicate notifications. The underlying trace retains its original attributes and may itself contain sensitive data.

For partial or otherwise incomplete sequences, a failed HTTP span with an integer `http.request.resend_count` of at least two produces a **possible** retry finding unless a matching observed span is a redirect. The finding separately reports the number of matching spans observed and the resend count indicated by instrumentation. The counter also includes redirects, so unobserved redirects can explain it; the finding explicitly says so. It does not claim missing attempts failed or report a total elapsed interval. Partial traces never use the sequential inference above.

Only HTTP spans with a full URL and an observed parent are considered; traces over 10,000 spans are skipped. Missing spans, instrumentation that does not record errors, non-HTTP dependencies, retries with longer backoff, and independently repeated failed operations can cause missed findings or ambiguity. No non-HTTP retry attribute is assumed without a reliable contract. Existing findings are upserted on reanalysis; as with other trace detectors, they are not automatically removed if later data contradicts an earlier finding.
