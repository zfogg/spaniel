# Timeout evidence

The timeout detector groups explicitly observed timeout spans connected through observed ancestry within a trace. Independent chains produce separate findings; ancestry walks stop at missing spans, cycles, or 1024 links. It recognizes exact deadline/timeout error types, exact context deadline status messages, and gRPC DEADLINE_EXCEEDED (4). Cancellation (including gRPC CANCELLED) is counted separately and never creates a timeout finding by itself. A successful immediate parent is reported as a possible handling boundary, not proof of recovery; an unset or missing parent is not treated as success. Summaries contain counts and fixed labels, never raw messages or attribute values. The representative span and its parent link to the trace inspector.

A representative span may supply `deadline.unix_nano` as a decimal string containing an absolute Unix timestamp in nanoseconds. Only a valid deadline after that span's start and a valid end time produce budget and remaining-time values. Negative remaining time means the span ended after the deadline. This application-defined attribute is not an OpenTelemetry standard; no budget is inferred when absent or invalid.

Partial traces are analyzed using only received evidence. Late arrivals can join previously separate chains; obsolete findings are removed on reanalysis. A leaf anchors each finding, preserving its ID when an ancestor arrives late. A new leaf or a merge can change the ID. The count is observed spans, not distinct incidents: propagation can produce multiple timeout spans. Only the representative span and its immediate parent are directly linked by the current finding model; inspect the trace for other evidence. Exception events are not loaded by trace analysis, so this detector uses span attributes and status only.
